# Agent执行手册

本项目面向两类Agent，二者均不获得用户的最终官网提交权。

## 开发Agent：读取仓库并完成任务

1. 阅读AGENTS.md、GOVERNANCE.md、产品需求、当前交接、CAPABILITIES.json与任务对应接口。确认请求属于哪项能力及现有实现位置；不从聊天标题或lab目录名猜项目。
2. 核对源码和测试，不把planned或partial说成全部完成。记录任务目标、边界、依赖、影响文件和验收；先搜索已有功能，复用原模块。
3. 使用自己的分支与虚构临时资料。不要初始化、迁移或读取另一使用者的.runtime，也不为验证程序擅自打开真实招聘页。
4. 实现后跑对应测试；更新权威规范/能力索引和唯一变更片段，检查新增入口和冗余定义。运行check_project、check_docs；在公开Git checkout做check_privacy --tracked。
5. PR说明问题、最终行为、兼容/迁移、实际测试和未覆盖范围。接续写明未完成项，不靠“下一位Agent知道上下文”。

不要求某一家模型供应商；编码Agent至少需要读取/修改工作树、运行所列Python/Node测试和理解接口。没有工具或权限时明确缺口，不能伪造验证。

## 运行Agent：接入现有产品

遵循[Agent协议](AGENT_INTEGRATION.md)，通过CAREER_AGENT_COMMAND的JSON argv接口接入，不能改成另一套资料库或任意网页脚本。接收任务的output_schema并返回合法结果；模型回答由程序核验后采用。

| 能力 | 要求 | 缺失时 |
|---|---|---|
| 结构理解 | 保留原文、日期精度、对象边界和证据，不补事实 | 返回失败，保留原件和旧资料 |
| 网站映射 | 理解对象、范围、版本、实际选项；引用已有合法记录 | 歧义显式返回，禁止猜填 |
| 公开检索 | 实际调用公开检索/打开工具，返回可核对的web_pages | 不支持则明确失败，不造网址或opened=true |
| 稳定传输 | stdin/stdout JSON、超时/失败不混入半份结果，诊断不泄露资料 | 不采用残缺输出，允许明确重试 |

任何人的Agent并不天然满足以上条件；具备能力、接口兼容、账号/网络/Chrome配置和本人授权后，才能尝试当前已实现范围。模型差异和未知招聘网站仍需单独验收，不能承诺读完文档即可自动获得全部能力。

## 接入验收阶梯

A. `python scripts/doctor.py`检查环境；新用户按SETUP初始化，已有运行资料不能重建。

B. 按TESTING安装依赖后执行 `python -m unittest discover -s prototypes/profile-lab -p test_agent_adapter.py`。这只是虚构适配器协议回归，不调用你的真实模型，也不证明其语义能力。

C. 配置自己的Agent，用虚构文档和表单分别检查结构提取、同名不同对象、日期冲突、来源原文、教育集合、版本和缺项。记录实际提供商/版本、输入范围与失败；回声示例仅测管道，不算通过。

D. 若提供公开检索，检查真实工具打开回执与岗位证据；不能仅依据Agent自报。然后在本机虚构表单走材料预览→本人确认→插件填写→回读，确认没有自动最终提交。

E. 经本人授权后，再对明确网站、材料和动作进行真实测试。填写、附件完成、当前回读、保存回执、重开后持久性分别报告。无草稿页面不能刷新；官网登录/验证码/协议/最终提交本人处理。

## 完成的定义

能力索引可定位所有列明模块、安装与协议可复现、有关检查通过、未支持项明确。一次局部成功不能将整个能力标为全网站支持；新增功能必须随代码、测试、文档和变更记录一起进入仓库。

## 接续命令是默认职责

每次新任务及恢复先运行project_handoff.py status、读取最新索引；写入前begin，交付或中断前record，并完成检查。参数与状态处理以[CONTINUITY](CONTINUITY.md)为准；用户无需重复要求记账。共享源码的登记与业务授权独立，不通过登记扩大真实模型/官网操作范围。
