# 流程与接入设计

本文件保留接入设计，已实现与未覆盖范围以 [产品验收](../../../docs/RESUME_SKILL_VALIDATION.md) 为准；业务语义以SKILL.md已确认规则为准。程序接口、字段表示与界面布局在实际接入时适配，不要求用户决定函数名、缓存键或JSON结构。

## 工作台中的位置

```text
我的资料：上传并要求解析
  → 原导入任务保存原件
  → MarkItDown转换，保留完整Markdown
  → 清理转换噪声并保留清理前后文本
  → 现有CodexRecognizer加载本Skill的解析规则，理解清洁文本并输出候选
  → 有归属/版式疑点时回查同一PDF/Word原件、页面和结构，仍不确定则保留问题
  → 程序核验原文、对象、格式与完整性
  → 本机对比当前已确认资料及其他待处理导入
  → 同一个工作台增量预览：复用已保留的相同表述；呈现新增、差异、归属与冲突
  → 确认同一对象后，对不同表述选择保留某版或多版（包括获奖等信息）
  → 汇总全部提示/疑点为可跳过表单；简称解释待确认、缺项可补充或留空
  → 用户完成识别确认，再按set选择保存；冲突对象可暂缓
  → 原资料服务原子入库并回读，更新同一任务处理结果
  → 我的资料：正常维护记录、整组版本与原附件
  → 开始某岗位投递：另一条网站理解流程按官网问题取用已确认资料
  → 本次材料预览确认 → 原执行器填写 → 用户本人最终提交
```

普通“附件上传/选择原件用于官网”不自动触发资料解析；用户选原件后仍按原附件流程上传。简历解析、网站表单理解、控件填写是三个不同职责，不让本Skill重新解析已确认资料来完成每次投递。

## 各阶段职责及接点

| 阶段 | 现有接点（首轮检查） | 接入建议 |
|---|---|---|
| 上传与任务 | /api/import，Lab.upload/start_import | 沿用任务ID、原件存储、进度及失败重试入口；不新增Skill独立上传页 |
| 转换 | document_markdown.convert_document | 继续MarkItDown；保留原始转换文本；清理装饰/噪声生成独立文本，不删改事实 |
| 模型提取 | CodexRecognizer.extract/call | 在现有识别请求加载当前字段契约＋相关Skill规则＋本次清洁文本；输出对象及证据候选，必要时做局部语义比对 |
| 核验 | grounded_candidates | 引用要落在该对象范围，日期不能仅靠全文出现；描述核对边界与覆盖；错误留在任务中，不冒充完成 |
| 增量比较 | reconcile_semantic_imports | 分别判断对象身份、事实与表述；已保留的相同表述复用，新表述进入版本取舍，疑似归属和事实冲突进入确认 |
| 人工选择 | /api/import/review、/identity、/resolve | 保留关联确认、增量决定、修订检查；整组选择保留一版或多版，覆盖获奖等信息；保留多版不新增另一条经历/获奖 |
| 入库与后续使用 | 原资料服务、现有资料/版本存储 | 适配现有整组版本服务，不能直接沿用旧逐字段增版；写后回读；网站映射只取已确认数据 |

表中的接口是已有入口，不表示新增行为已实现。接入前重查主产品最新实现；如果接口发生变化，就适配新接口，不恢复历史入口。

## Skill怎样真正进入模型请求

当前识别器关闭了隐式Skill加载，因此把目录放入skills目录并不能使工作台使用它。

建议在现有识别器构建请求时，显式加载本Skill中受控的解析规则。维护一个权威规则来源，程序引用或可验证地生成请求文本，禁止再手抄一份长期独立提示词。接入评审、待决定事项、历史诊断不全部塞进模型上下文。规则版本与字段契约版本随识别任务记录，便于判断结果是否可复用。

依旧关闭文档发起工具操作的能力，不开放用户机器上所有Skill，不换供应商。把规则嵌入已有识别请求，避免另起Agent重复完整识别；这是一项减少重复工作的实施建议，“不增加模型调用”不是用户要求，也不是调用次数的硬限制。需要额外语义判断时可以设计必要的局部模型调用。Skill既规定模型输出，也为现有本机核验/增量服务提供实现依据，但模型不能代替事务或自行写库。

首次请求只提取本次文档；优先在本机复用已有结果，不自动发送整库。确定性比对不足时，可在现有授权范围内向约定模型提供相关对象的最小必要原文及候选，做有界的语义比较，不重跑全部简历。仍缺证据则保留“归属待确认/差异待确认”，不能用公司或项目名相同强行合并。模型判断同一信息也不能代替用户选择表述版本。额外调用记录目的、范围、耗时及可获取的用量；具体已验证范围见产品验收，不能将设计等同于所有输入均已通过。

## 速度、失败与恢复

- 转换与识别分别复用：以内容、转换器版本、规则版本和字段契约判断结果是否可用，文件名不能作唯一依据。
- 仅底稿或用户决定变化时，复用文档提取结果，重算受影响的增量比较；需要语义判断时只比较相关片段，不重新发送整份简历。只修来源校验时复核已保存模型结果，不默认重跑模型。
- 规则变化不批量重解析历史已确认资料。对未确认任务，只有受影响的阶段需要重试；不能声称旧规则结果已按新规则重新识别。
- 保留完整Markdown供核验，长文预览截断不等于输入可截断。长文拆分需要验证对象边界及合并后的完整性，不能为提速丢内容。
- 超时、连接失败、转换失败、核验失败分别展示；完整模型终态与残缺输出区分。沿用当前重试机制，本草案不新增无限自动重试。
- 已保留的相同表述不重新问；同一事实的新表述仍需用户选择保留哪版或多版，不能被语义去重吞掉。冲突对象不阻塞其他确定对象保存；本次官网缺项仍可留空并填写其他已确认独立项。
- 忽略按来源导入任务保存，不作跨未来导入的永久指纹屏蔽。多个来源合并展示时，决定仅覆盖预览中的这些来源；独立新导入重新比较并提示未入库候选。适配旧全局ignored_candidates时保留历史任务决定，不批量重置或重新解析资料。
- 各阶段分别计时、计数；Skill改善重复工作和规则一致性，不承诺网络时延或任意简历固定耗时。

## 接入验收与范围

先用虚构文件验证相同输入的对象和事实一致、原文完整、归属核验、普通保存不自动增版、同一信息不同表述的取舍（含获奖）、增量复用、旧预览失效、确认重放及回读，再在隔离工作台走完整上传链路。保留多个获奖表述必须仍是一条记录，各版可用于后续选材，原附件完整；没有明确默认选择时，下游不能擅自挑最新版。必须证明请求实际使用目标规则版本，不能只通过Skill格式检查就称已接入。

最终只有一个活动资料库、一套正式导入入口和一套填写执行器。临时测试夹具不成为产品第二套资料；本轮已按用户明确授权接入并进行隔离测试，活动已确认资料未重解析或覆盖。
